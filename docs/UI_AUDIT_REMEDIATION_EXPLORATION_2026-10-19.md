**Disposition completed (2026-10-20) per the deprecation protocol:** all six files (`OCRSearch`, `MobileNavigation`, `SidebarNavigation`, `TopNavigation`, `ProvenanceChips`, `ProvenanceChip`) now carry `@deprecated` JSDoc headers stating the superseding surface, the evidence, and the removal condition ("removal candidate after one release cycle" — except the Provenance pair, which is held as the design reference for the future photo→source backend, reactivatable rather than deletable). **Update 2026-10-21 — the "future photo→source backend" is no longer future, so the Provenance pair was superseded rather than deleted for being dead.** The registry already held the truth; the work was to join it to the photo payloads. `ProvenanceChips.tsx` deleted, `ProvenanceChip.tsx` rewritten to render the real record and mounted in the photo detail; `server/attribution.py` + `/attribution` + `/attribution/batch` + `attribution` on `/browse` and `/search` items. 4. **Provenance — SPLIT 2026-10-21, partially resolved.** The gap was two problems wearing one name:
   - **Source attribution** (which library is this file from) — **RESOLVED 2026-10-21**. The truth already existed in the registry (`SourceStore` + `SourceItemStore.find_by_local_path`); it was simply never joined to the photo payloads. The fabricated pair is retired: `ProvenanceChips.tsx` deleted, `ProvenanceChip.tsx` rewritten to render the real record and mounted in the photo detail ("Origin").    - **Content provenance** (C2PA authorship manifests) — still **OPEN by design**. `server/content_provenance.py` does *detection only* (manifest marker present/absent, `verified: false`, explicit note that no verifier ran). Verification needs a C2PA SDK and trust list; a half-verifier that claims "signed" would repeat the exact fabrication the chips were retired for.
5. **No OCR settings endpoints** (language thresholds etc. are per-request params only). OPEN.
6. ~~**Duplicate route registrations** in `locations.py`~~ — **RESOLVED 2026-10-20**: both shadow registrations removed (unreachable: identical paths registered earlier; frontend consumes the first shapes). Route table verified duplicate-free; TestClient 200s on both paths.
7. ~~**PrivacyControls `btoa` "hashing"**~~ — **RESOLVED 2026-10-20**: client now sends a real SHA-256 hex digest (WebCrypto, secure-context-guarded). Server verified to treat `encryption_key_hash` as an opaque optional string (stored/passed, never compared), so old base64 values are simply overwritten on the next save — no stored-value migration needed. Empty-key guard added.
8. ~~**`PersistentJobStore` shared main-thread SQLite connection**~~ — **RESOLVED 2026-10-20**: per-thread connections via `threading.local` (property keeps the `self.conn` API), WAL + `busy_timeout=5000`. ## 5. ESC/modal layering notes (for anyone touching useModalBehavior)

- Hook listens on `document` with capture + `stopPropagation`, so it pre-empts `window`-level handlers; per-instance `open` expressions are how stacking works: a lower layer must detach while a higher one is open (PhotoDetail: `open={!!photo && !showExplanation}`; CollaborativeSpaces: `closeDetails` no-ops while invite/add-photo is open).
- 4 portal modals mount through `createPortal` — the hook's focus-restore returns to the correct in-lightbox trigger.
- Popovers (SearchModeHelp, PhotoGrid select menu, PhotoGlobe help) intentionally do NOT use the hook (no focus trap/`aria-modal`) — Escape + ARIA only.
- Tests: `ui/src/test/useModalBehavior.test.tsx`; jsdom needs a `getClientRects` stub (no layout engine) and one composite-Tab assertion was removed as a jsdom-interleaving artifact — the two directional wrap cases are each covered in isolation.

**Observed while capturing (not fixed here, feed the desktop/web plan):**
- **CORS kills every non-dev web origin.** A production `dist/` served from `127.0.0.1:4173` is blocked by the API (`No 'Access-Control-Allow-Origin'`); only the Vite dev origin and the Tauri origin work. There is no production web deployment path today.
- **Mixed API addressing.** Most calls use the absolute `VITE_API_URL` base; some (`/api/actions/detect-apps`, the demo's `/api/code-splitting/*`) are same-origin relative — they can only work behind the Vite dev proxy and would fail inside Tauri's asset origin.

- **FirstRunModal stacks under page content** on a fresh origin: the 404 text renders crisply on top of the dimmed modal (z-index/stacking defect, pre-existing).
- **API host default drift is configuration, not code**: HEAD build reported `127.0.0.1:8000`, working tree `localhost:8000`. Corrected attribution (2026-10-21): the difference is the **gitignored `ui/.env`** (`VITE_API_URL=http://localhost:8000`), which `git archive` excludes — `api.ts` itself was never modified. Host choice interacts with CORS allowlists and IPv6 resolution; resolved by the platform-boundary work (`resolveApiBase`, decision doc 2026-10-21).
